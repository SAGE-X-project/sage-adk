# Approved operation policy and loaded instance binding

This change connects protected request capture, executable local allow/deny
rules, approved artifact bytes and the native tool host. It implements no new
wire fields and changes no SAGE 0.10.0 obligations. The normative source remains
`sage-spec` `1820ab5eafb843e1c13f4c46c34aeeb28d934ac9` (EXEC-01/02/06).

`core/guardbinding.Open` receives a trusted captured Request, independently
approved policy/component descriptors, a protected artifact directory, finite
byte limits and a trusted Factory. It refuses changed/missing/symlink/non-regular
files and inconsistent shared paths. It reads an exact owned snapshot, checks
both commitments and passes copies to the Factory. A loader must produce one
fixed instance and verify the actual loaded policy evaluator, tool and dependencies
against both commitments. Snapshot hashes alone cannot establish code loading
or OS isolation; the Factory's loaded-instance Check is mandatory.

The local engine `sage-adk/exact-operation/1` reads the policy artifact
`rules.json`. Its closed local JSON format contains version, recipient, keyid,
tool, arguments and max_lifetime. It permits only that exact recipient/tool/
canonical argument object, with the configured lifetime bound and signing key.
This is an optional local evaluator, not a universal policy language or a new
portable permission. Trusted administration selects its rules independently of
model output and includes evaluator/rule/config/dependency artifacts. It does not
prove natural-language equivalence or confer authority from an original digest.

The operation implements core IssuancePolicy and IntentMeasurement. Its private
LoadedTool wrapper supplies a native Binding, rechecks capture, rules artifacts,
component artifacts and the same instance immediately before exact arguments
reach that instance. No policy replacement, loader lookup, raw instance getter
or unsigned Execute method is exported on Operation. Binding itself is trusted
host configuration and must never be exposed to model/plugin code.

A shared mutex serializes checks, bounded execution and Close. Close waits for
an already accepted effect/cleanup and permanently retires the operation before
closing its directory handle. Later callbacks fail. It cannot undo a committed
effect. Before replacement/recovery administration must stop native host workers,
retain ledger/issuance fences, retire the old mapping across receivers and
provision a fresh approved epoch where required. This volatile helper does not
durably install policy epochs or solve distributed retirement/recovery.

Tests first: strict rules/descriptors, finite limits, exact hash/file set,
defensive snapshots, failed loader/attestation, changed capture/files, exact full
unsigned intent, cancellation, panic and retirement versus in-flight inert
execution. Safe runtime: real private artifact files and the existing ephemeral
Ed25519/X25519 native loopback fixture, protected issuance, exact arithmetic
arguments, signed verified result and durable recovery. Denial scenarios for
changed policy/instance boundaries remain units. An external library consumer
checks public assembly. Existing registry and attestation fixtures remain
fixtures; no selected deployed host, blockchain observation, independent hop
execution or complete conformance verdict is promoted.
