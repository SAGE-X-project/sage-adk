# Original request capture and Guard issuance

The trusted input owner must preserve the ordered UTF-8 input bytes before a
message decoder, model or plugin transforms them. This change adds that boundary
to the ADK without changing existing transport or tool APIs.

## Sources and scope

- Normative SAGE 0.10.0 source: sage-spec commit
  `1820ab5eafb843e1c13f4c46c34aeeb28d934ac9`.
- Public Go core: `11b1cd91691de99fdbd734db78dc6755c187b2e9`.
- ADK baseline: `a7368f78fc87e3098ca8eba22c5fc47fdd214179`.

`capture.Host` generates a fresh UUIDv4 and stores a defensive copy of the exact
input list before returning an opaque `Request`. Readback must match the initial
commitment. A Store atomically reserves each ID and has write-once, durable
Create and bounded Load operations. Incomplete in-flight or failed records may
be refused; a request/checkpoint is published only after successful persistence
and verified readback. The included FileStore uses a private directory, exclusive regular
files, file and directory synchronization, bounded records and no-follow opens.
It never overwrites or automatically deletes an interrupted record. Restore uses
a request ID and digest from a protected host operation checkpoint; an unverified
wire envelope is not a checkpoint. FileStore creation also synchronizes the new
directory entry in its existing parent.

`Request.NewIntentIssuer` supplies the core RootCapture and wraps both policy
providers and signing custody with fresh original-input checks. It requires all
existing core services; capture does not grant policy permission or select a key.
The core continues to own canonical intents, recipient/key constraints,
one-use approval and the durable issuance fence.

`agent.ProcessOriginal` stores input before invoking a host-supplied decoder,
then checks the stored original again before invoking the ordinary message
handler. It returns the capture capability only to the trusted caller. Legacy
Process, servers, direct LLM calls and tool execution remain separate APIs. They
are not made non-bypassable by this change.

## Trust boundary

The caller must capture actual user input before any untrusted expansion, protect
Store/Request/issuer/policy/key capabilities, and serialize trusted administration.
File permissions do not isolate code running as the same OS user. Protect the
storage directory and its ancestors from untrusted writers and rollback; all
ancestors must already exist, and the supplied directory must not be a symlink.
The store is plaintext and retains potentially sensitive input; the host controls
access and retention. Providers must be bounded, honor cancellation and must not
mutate trusted state during an operation. Fresh digest checks detect divergence
from the captured bytes, not a compromised initial capture or concurrent hostile
key custody. No host attestation or protected deployment claim is made.

## Verification and sequence

1. Unit scenarios: exact framing, copies, fresh IDs, store failures, invalid input,
   cancellation, malformed files, changed originals and policy-binding mismatch.
2. Safe runtime: disk reopening, local Ed25519 issuance and external module use;
   no live registry, model, network send or executable tool effect.
3. Full build, vet, race suite and Linux/macOS CI.
4. Next: trusted final tool-effect mediation, deployment control bindings and
   Inspector runtime evidence. The historical readiness results stay unchanged.

The repository's existing aggregate coverage is below its 90% target. Coverage
for new capture code is measured separately; passing local fixtures must not be
reported as complete SAGE 0.10.0 implementation conformance.

## Local verification result

- `go mod verify`, full readonly build and `go vet`: passed.
- Full `go test -race -coverprofile=... -timeout 10m ./...`: passed.
- External consumer `go test -race -timeout 1m ./...`: passed, including real
  temporary-file persistence and reopening after Close.
- `core/capture` statement coverage: 90.7%; original agent entry: 95.2%.
  Aggregate coverage including legacy/generated/example code is 53.2%, below
  the repository target; this change does not claim that existing gap is closed.
- CLI binary: built and printed version 1.2.0.
- Dependency versions and go.mod are unchanged. New Guard imports require three
  additional checksum lines in each module's go.sum, recorded after tidy.

The issuance fixture uses an ephemeral local Ed25519 key and an inert proposal.
It checks the durable issuance fence before key use, the signed request ID and an
independently calculated original commitment. Changed originals, unavailable
custody, policy mismatches and missing/typed-nil services refuse signing. File
scenarios stay in temporary test directories; there is no live tool or network
send. Linux/macOS CI repeats the full suite and external consumer before merge.
