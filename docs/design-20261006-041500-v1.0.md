# Public core dependency migration

## Scope and references

Restore clean-checkout ADK builds before connecting the SAGE 0.10.0 Guard.
Reference SAGE public packages at `11b1cd91691de99fdbd734db78dc6755c187b2e9`
and published `trpc-a2a-go v0.2.2` (`2503fe48ceca4d2b811f0aa5e5770d2ada9304d9`).
The inspected local fork revision is not published. The current public SAGE A2A
fork has a different API and module path. Retain the ADK's existing tRPC binding
using its published upstream release; moving to the newer fork belongs to the
later planned A2A migration. No sibling checkout or SAGE internal package is required.

## Interfaces and changes

- Import SAGE from `pkg/agent/{core,crypto,did}` with a pinned module revision.
- Compose key generation, PEM/JWK codecs and storage directly from public packages;
  remove process-global constructor registration. `KeyManager.Manager()` now returns
  the ADK facade, since the old SAGE `crypto.Manager` type no longer exists.
- Retain the adapter's embedded `Config` field using ADK-owned `configmodel` DTOs.
  Consumers constructing this field migrate their import from `sage/config` to
  `sage-adk/adapters/sage/configmodel`; it is not a core application configuration.
- Use the public AgentCardClient and preserve distinct signing and KEM resolution.
- Resolve the existing A2A binding from a published version with no replacements.
- Include generated protobuf bindings from the existing ADK schema so clean
  builds do not require code generation; align examples with existing ADK APIs.

## Remaining boundaries

The ADK owns the HTTP server using the published A2A handler because both
upstream v0.2.2 and v0.2.5 mutate an unsynchronized lifecycle field. Default
examples also required missing builder metadata methods, current agent methods
and repaired roles/variable references. Legacy gRPC now shares the existing
timeout/retry options and includes its missing stream interface. These are
compatibility repairs, not newly protected transports. A real loopback request
also exposed pointer-valued decoded parts losing their text and an absent response
message kind; both are repaired with a serialized-request regression check.

The old ADK JSON/BLAKE3 envelope and legacy RFC9421-named helper are not evidence
of RFC 9421 HTTP or SAGE 0.10.0 conformance. Existing optional signing, missing reply
implementation, nonce handling and direct tool execution remain legacy limitations.
Protected use must wait for independent capture, current registry/key custody/policy
providers, Guard owner admission, final effect gating and Inspector runtime evidence.
Deployment controls and independent hops remain NOT_RUN; full conformance remains
NOT_ESTABLISHED. No normative spec changes or demo rollout occur in this migration.
