# Protected A2A 1.0 binding

The normative basis is sage-spec `06b50e177ccd22bce7d70fd80c2d7f822ae3fd3b`,
A2AB-01 through A2AB-07. A2A v1.0.1 publishes protocol version `1.0`;
its specification and protobuf hashes are the adopted proposal's pinned hashes.
Existing A2A adapters and chapter 07 card proofs are distinct legacy surfaces.

Add `core/a2abinding` as an explicitly protected library boundary. The module
checks the closed AgentCard model and protobuf presence rules, reconstructs
JCS without signatures, verifies exactly one SAGE JWS using a fresh configured
Source, and offers only interfaces exactly present in that record's services.
Ed25519 is strict; P-256 uses raw low-S ES256. No JOSE EdDSA, secp256k1 card
signatures, card-supplied key source or fetched binding URI is accepted.

The schema table is derived from the pinned AgentCard dependency closure,
including security schemes. Optional default values remain present; required
fields remain present; ordinary defaults are omitted. Raw JSON is bounded,
rejects duplicate/alias duplicate members, invalid UTF-8/surrogates,
negative-zero tokens and non-finite numbers before any lossy parsing. Card
issued/expires and JSON-RPC id/code integers are checked exactly before JCS. Executed request models also enforce protobuf integer widths and required
fields. Card nulls are rejected as required by A2AB-04; request ProtoJSON
nulls leave known optional fields unset, and Value retains its null datum.
Quoted int32 values follow the standard parser plus exact arithmetic checks.
Application state and method-specific semantics remain the handler's
responsibility. REQUIRED arrays are nonempty independently of presence rules.

A protected client performs fresh card verification for each call, carries
exact JSON-RPC bytes with version/extension metadata to a mandatory local
transport owner, and never invokes the legacy selector or retries on another
interface. The owner's contract is the chapter 03/08 authenticated HTTPS
request/response carriage, replay transaction, response binding, and session
lifecycle. These responsibilities cannot be inferred from a card signature.

A server policy boundary accepts only the owner's authenticated request view,
checks the recipient, signed metadata, configured interface and tenant route,
and dispatches allowed A2A methods. Streaming, push and extended-card methods
return the A2A unsupported-operation response, inside the protected transport
result. Binding failures have one generic local error and no application call.
A2A errors remain JSON-RPC results, not SAGE transport errors.

Trusted Source, clock, transport owner, tenant routing and application handler
are explicit deployment inputs. This library does not choose a contract/RPC,
custody, TLS identity or unprotected fallback. The existing core bounded session
API does not expose this A2A metadata integration; a production transport-owner
adapter and deployed qualification remain explicit integration work. Safe TLS
fixture tests test this policy boundary, never certify the real Source or owner.

Implement tests before production code, run race/coverage plus safe separate
process or TLS loopback tests, require new-code statement coverage >=90%, and
perform independent read-only LLM review before CI and squash merge. Inspector
observation is the next approved work item; no new spec or contract change is
included here.

## Using the library

Construct a Verifier with a configured `advanced/sage.Source`, protected clock
and expected peer. The Go core's pinned `didsource010` adapters can supply this
Source. Create a Client with a mandatory TransportOwner, then call it with card
JSON and the exact A2A JSON-RPC bytes. A configured interface tenant must be
present exactly; a tenant absent from the interface must be omitted. Each call
revalidates the card before the transport owner's final send gate.

The Server runs after the owner's cryptographic receive transaction. It checks
its configured card and routing, validates request models before dispatch, and
leaves task/state semantics and effect authorization to its Handler/Execution
Guard. JSON-RPC response syntax, id and error shape are checked; result/task
semantics remain the application consumer's responsibility. ProtoJSON aliases
are validated as one semantic field, and policy checks use the normalized model
while dispatch preserves the original authenticated bytes.

This client understands SAGE only and refuses other required extensions;
servers return A2A -32008 for an inactive non-SAGE required extension after
binding checks. Streaming, push configuration and extended cards return -32004;
push configuration inside SendMessage returns -32003. Handler failure or a
malformed local application reply returns a generic JSON-RPC -32603 inside
the protected result; it is not mislabeled as a binding authentication failure. No failed call retries
on another interface, binding, version or unsigned card.

## Validation and limits

The safe runtime is a separate test TLS connection with an explicitly marked
`fixture-policy-only` owner. It exercises the public client/server policy,
exact payload, fresh observations, unsigned-hint exclusion and refusal without
application effects or retries. It does not implement chapter 03/08 carriage
or prove its signatures/replay; those are explicit production owner obligations.
No vulnerability reproducer, host bypass, external service or real transaction
is included. Actual Source/owner/Execution Guard readiness remains NOT_BOUND,
and deployed protection remains NOT_RUN.

Independent read-only LLM review found tenant presence loss, required empty
arrays, a push field alias mismatch and incorrect non-SAGE extension error
classification. The fixes have regression scenarios, and the reviewer reran
the package with race/TLS tests successfully without remaining findings.
Coverage is checked for each new production file, excluding test statements.
The request/card field table can be regenerated only from the pinned protobuf
hash using `verification/a2a-basis/generate_schema.py`; it changes no normative
SAGE spec or the existing legacy A2A adapter.

ProtoJSON input behavior follows [the primary format documentation](https://protobuf.dev/programming-guides/json/); the stricter card null/duplicate restrictions come from the adopted SAGE binding.

Local final validation on Go 1.26.8 passed all 34 tested ADK packages with
race detection, the external library consumer, build, vet and module verification.
The new module has 16 top-level tests with additional scenarios and safe TLS
runtime coverage. Every new production file exceeds 90% statement coverage.
The core dependency is pinned to `4c7bad17ce176088f7bbc22c94814a0631cd8776`,
and both root and external consumer keep Go 1.26.8. An empty ExpectedPeer proves
only control of the named DID; it cannot bind that DID to an arbitrary card host.
