## Design

Add core/guardservices with a single process-owned SystemClock implementing
registry Clock and Guard ClientClock. All host services share this instance and
monotonic origin. UTC milliseconds are sampled with monotonic elapsed time;
clock rollback or invalid ranges permanently refuse further samples. Cancellation
refuses a call without poisoning future healthy calls. No time clamping or
peer-provided time is used.

Separate IntentSigner and ResultSigner adapters require a concrete protected
RegistryAuthority and a fixed Ed25519Backend exposing only public bytes and
bounded context-aware signing. Construction checks current role-bound Ed25519
public bytes. Each signing call rechecks backend correspondence and authoritative
activation before key use, verifies the returned proof, and rechecks authority
before publishing it. Only the relevant domain-separated canonical JSON object
with the configured issuer/keyid/version/algorithm is accepted. Intent policy,
opaque approval and durable issuance fencing remain the core issuer's duties;
these low-level signer capabilities stay with the protected host.

No key import/export API, KEM fallback, private-key access, default policy,
local Registry assertion or unconditional approval is added. The backend and
Registry Source remain deployment-owned, bounded, immutable, cancellation-aware
and non-reentrant. No wrapper creates OS isolation, proves HSM custody or
completes a blockchain Registry observation.

Use the adapters in the existing inert native tool runtime and external public
consumer. Scenario units cover missing/mismatched/revoked keys, provider failures,
panics, cancellation, wrong domains, mutated bytes and clock regression. Run
full race tests, build, vet, public consumer and Linux/macOS CI before squash
merge, branch deletion and original main synchronization. Keep all Inspector
historical evidence unchanged. Real Registry deployment and effect inventory
remain subsequent bindings requiring the requested deployment information.

## Verification record

Go 1.26.8 full race tests, readonly build, vet, module verification and the
external public consumer pass locally. New guardservices coverage is 95.9%;
toolhost is 95.8% after the runtime uses the registry-bound adapters. The
repository-wide legacy coverage gap remains and is not closed by these tests.
Public dependencies and the normative specification pin are unchanged.
The unit fixtures control revocation during signing, cancellation, provider
failure and key-role rejection; no attack-capable reproduction is introduced.
The normal runtime uses injected fixture time to honor replay quarantine;
the real SystemClock is checked separately through both public interfaces.
Linux/macOS CI is required before merge. A real blockchain Registry deployment
has been requested and remains unspecified; deployment verification is not run.
