# Guarded tool execution through the native owner

Original capture and issuance are available in ADK main `d0cdd3c844afa2a7f63e1452134317e20ccefd49`.
The legacy tools.Registry exposes callable objects and executes unsigned maps.
This change adds a separate guarded host backed by the public native MCP owner
in Go core `11b1cd91691de99fdbd734db78dc6755c187b2e9`; it preserves the normative
SAGE 0.10.0 pin `1820ab5eafb843e1c13f4c46c34aeeb28d934ac9`.

## Boundary and APIs

`toolhost.Open` accepts protected authority, policy, result signer and clock
services, finite native bounds and immutable tool bindings. Each binding pins a
name, approved manifest digest and one LoadedTool instance implementing both
measurement Check and Execute. No tool getter, unsigned Execute, executor
replacement or permissive default is exposed. Models receive proposals/schemas,
not Host, raw tool instances, policy, signer or connection capabilities.

Connect/Serve/Close delegate lifecycle and encrypted private length-framed MCP
carriage to the existing core host. The core owns durable reservation, final
admission, fixed workers, UNKNOWN recovery and signed result consumption. A tool
is invoked only inside a live admitted worker. Immediately before Execute the
ADK adapter checks the private live admission, freshly verifies the signed intent
against current authority/policy/time, checks the same loaded instance, and checks
admission/cancellation again. Exact canonical argument bytes reach Execute;
there is no conversion to unsigned maps or addition of defaults. Output must be a
bounded canonical JSON object before the native owner signs and stores completion.
Exceptions, invalid output and cancellation return errors to the native owner;
there is no retry or fabricated success.

`capture.Request.OpenMCPClient` reloads the original and reopens the existing
issued Client journal through one authenticated connection. The old Client must
first close successfully. Identity and operation path stay unchanged; there is
no missing-journal creation or fallback. The Client policy retains fresh capture
checks on subsequent handoffs. This is a close-and-reopen transfer on protected
storage, not an atomic transfer across processes; the host serializes ownership
and protects the permanent issuance fence, journal and original checkpoint.

## Scope and trust

This supports the core's native private MCP carriage only. Existing A2A, HTTP,
stdio, legacy Registry and direct LLM/tool callbacks do not automatically use it.
The host must inventory supported effects and withhold raw executor handles from
untrusted code. No Go wrapper provides OS isolation against same-user code.
A manifest digest cannot prove which code is loaded; LoadedTool.Check must verify
its protected baseline, actual pinned instance and dependencies. Providers must
be bounded, concurrent-safe, non-reentrant, cancellation-aware and immutable until
Close succeeds. Failed Close retains native ownership/locks until cleanup ends.
The host supplies authoritative registry sources and protects secrets and storage;
local fixture services are not production providers or deployment attestation.

## Local verification record

Full readonly build, vet, module verification and the complete race suite pass
with Go 1.26.8. Toolhost coverage is 97.2%; capture is 90.7%. Repository-wide
coverage is 53.7%, with the existing legacy, CLI, storage and generated-code gaps
still present; this change does not establish the repository-wide 90% target.
The independent consumer module passes through public pinned dependencies and
only replaces the ADK checkout. Its positive runtime fixture mirrors the root
fixture, so it is packaging evidence rather than an independent spec oracle.
Root unit scenarios additionally refuse changed measurements, failed policy,
provider panic/error, invalid/oversized output and cancellation. Terminal Client
handoff is refused and completed/UNKNOWN ledger states survive clean reopen.
A new replay store's mandatory 360-second quarantine is modeled by the injected
fixture clock before issuance/setup; production validation is unchanged.

Remaining acceptance work is Linux/macOS PR CI and main CI after squash merge.
Deployment provider/effect inventory and Inspector subject selection follow as
separate work; these local checks do not revise historical readiness evidence.

macOS PR CI exposed an invalid fixture expectation: calling Exchange after a
terminal intentionally retires the native connection, so Connect must also fail.
The positive runtime no longer performs that deliberate failure. A separate
root unit scenario requires the terminal call to be reached, refuses its output,
expects connection retirement and verifies one effect plus COMPLETED recovery.
